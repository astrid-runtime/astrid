Empty per-runtime connection, listener, and IPC-limiter registries no longer allocate DashMap shard arrays at construction. The four maps live behind `OnceLock` and initialize with default `DashMap::new` on first insert or quota-bucket lookup after the payload hard cap; idle reads, unbind, listener drop, pool reset, and oversized-payload rejection leave them unset. Interceptor pools still clone one shared identity/lifecycle registry, run-loop workers keep private maps, and `bind_workers > 1` still leases one OS listener. `HostState`'s three registry field types and constructors change from `Arc<DashMap<...>>` to `Arc<OnceLock<DashMap<...>>>` as an intentional in-crate host-state representation; WIT, guest ABI, limiter quotas, and `IpcRateLimiter::new` stay unchanged. After first publish a used limiter still owns one default map; unused network maps stay unallocated. Closes #2267.
