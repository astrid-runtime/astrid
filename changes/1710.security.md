# Security

- Bound process storage projection reuse and drain to the immutable acting UID,
  provider generation, durable owner, and complete typed target set.
  Tracking #1710.
- Kept user-private state excluded from process provider projections and
  retained revoked projection leases when cleanup fails; retained state blocks
  duplicate projection creation until cleanup succeeds. Tracking #1710.
- Rolled back every issued branch, owner-home, and Fleet-shared lease when a
  provider launch fails. On retained provider teardown, immediately fenced
  every exact published lease so authenticated callbacks and renewals fail
  stale-lease while provider handles and resources remained available for
  bounded retry. Tracking #1710.
- Reclaimed stale native process storage roots only through singleton-owned
  boot, using the same no-follow, mount-boundary-aware validation used for
  principal runtime scratch; lockless injected kernels preserve another live
  kernel's roots. Tracking #1710.
- Retained admitted callback filesystem jobs across callback-connection
  cancellation. A drain timeout or filesystem-worker join failure reports
  cleanup failure at `drain` and leaves the exact revoked UUID root, provider
  resources, and mutation blocker mapped; exact retry completes only after
  jobs and the fence finish. Tracking #1710.
- Closed the retain interval after initial projection validation but before
  reference acquisition: authorized revocation or expiry performs exact
  cleanup and admits a replacement in the same mount request, without acquiring
  a stale reference. Provider drift or incomplete cleanup remains an
  administrative blocker. Tracking #1710.
- Removed the public raw process-storage remover. The kernel-private validated
  cleanup is admitted only by the existing private native singleton gate;
  arbitrary `Some(File)` resources cannot manufacture boot ownership.
  Tracking #1710.
- Made uncommitted OwnerHome and Fleet-shared issue rollback retain the exact
  revoked lease set on cleanup failure. Resource removal and map removal are
  now two-phase, so no member loses mapped authority before the whole issue set
  is resource-free; the retained blocker admits replacement only after exact
  cleanup succeeds. Tracking #1710.
- Restricted process-storage reclamation to a private native composition
  token; public `Some(File)` resources cannot manufacture boot ownership.
  Tracking #1710.
- Prepared Fleet shared storage, private HOME, parent tokens, and mount
  admission before allocating a provider-service UUID root. Tracking #1710.
