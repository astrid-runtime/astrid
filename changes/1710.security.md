# Security

- Bound process storage projection reuse and drain to the immutable acting UID,
  provider generation, durable owner, and complete typed target set.
  Tracking #1710.
- Kept user-private state excluded from process provider projections and
  retained revoked projection leases when cleanup fails; retained state blocks
  duplicate projection creation until cleanup succeeds. Tracking #1710.
- Rolled back every issued branch, owner-home, and Fleet-shared lease when a
  provider launch fails. On retained provider teardown, immediately fenced
  every exact published lease so authenticated callbacks and renewals fail
  stale-lease while provider handles and resources remained available for
  bounded retry. Tracking #1710.
- Reclaimed stale native process storage roots only through singleton-owned
  boot, using the same no-follow, mount-boundary-aware validation used for
  principal runtime scratch; lockless injected kernels preserve another live
  kernel's roots. Tracking #1710.
- Retained admitted callback filesystem jobs across callback-connection
  cancellation. A drain timeout, filesystem-worker join failure, or inner
  `spawn_blocking` panic reports cleanup failure at `drain` and leaves the
  exact revoked UUID root, provider resources, and mutation blocker mapped;
  exact retry completes only after jobs and the fence finish. Tracking #1710.
- Closed the retain interval after initial projection validation but before
  reference acquisition: authorized revocation or expiry performs exact
  cleanup and admits a replacement in the same mount request, without acquiring
  a stale reference. Provider drift or incomplete cleanup remains an
  administrative blocker. Tracking #1710.
- Separated projection startup serialization from the projection-cache guard
  so retain can never re-enter that guard while mount owns it. This preserves
  singleton provider startup while first-mount revoke and expiry intervals
  exact-clean and admit their replacement without deadlock. Tracking #1710.
- Removed the public raw process-storage remover. The kernel-private validated
  cleanup is admitted only by the existing private native singleton gate;
  arbitrary `Some(File)` resources cannot manufacture boot ownership.
  Tracking #1710.
- Made uncommitted OwnerHome and Fleet-shared issue rollback retain the exact
  revoked lease set on cleanup failure. Resource removal and map removal are
  now two-phase, so no member loses mapped authority before the whole issue set
  is resource-free; the retained blocker admits replacement only after exact
  cleanup succeeds. Tracking #1710.
- Restricted process-storage reclamation to a private native composition
  token; public `Some(File)` resources cannot manufacture boot ownership.
  Tracking #1710.
- Prepared Fleet shared storage, private HOME, parent tokens, and mount
  admission before allocating a provider-service UUID root. Tracking #1710.
- Verified the exact Windows provider executable, not only its trusted parent
  chain, before launch. A trusted path containing an untrusted writable or
  `WRITE_DAC` file ACE fails closed while regular-file, no-redirect,
  ownership, parent-chain, and Unix file-mode checks remain unchanged.
  Tracking #1710.
- Consumed a retained `Drain`/`JoinFailed` before projection teardown,
  unhealthy cleanup, partial issue cleanup, or principal deletion removes any
  exact lease, resource, UUID root, provider handle, cache blocker, or admits
  replacement. A later worker-join failure deterministically upgrades an
  earlier drain timeout, and principal deletion reports the typed failure while
  retaining identity, profile, revoked lease, and resources even when a stale
  listener says it is already closed. Tracking #1710.
- Kept an authoritative UUID-root blocker after exact issued-lease cleanup
  when root removal fails. One rollback result covers synchronous
  Branch/OwnerHome/FleetShared issue errors with their exact issued component
  set; Branch carries the empty set. The retained blocker denies replacement
  while no component lease remains mapped and admits only after an exact retry
  confirms both component cleanup and root absence.
  Tracking #1710.
- Serialized drain settlement through a per-lease monotonic outcome machine.
  Every cleanup and concurrent consumer samples the highest-severity failure
  before honoring listener closure, `JoinFailed` permanently dominates
  `TimedOut` until an exact retry consumes it, and cleanup success retires the
  latch. Workspace, owner-home, and Fleet-shared mountpoint preparation exits
  after UUID-root creation use the same retained zero-lease rollback path.
  Tracking #1710.
