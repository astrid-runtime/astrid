Added kernel-private audit-chain mechanics for native security events:
a versioned, injective, bounded, length-delimited canonical codec; a rolling
BLAKE3 root whose tag binds algorithm id, codec version, boot/session identity,
and sequence; one atomic mutation-side transition that commits frame, checked
non-wrapping `audit_seq`, and root advance together or fails before commit; and
a kernel-owned fixed-capacity relay with checked cursors, credits/acks,
bounded redelivery, and generation-bumped resync.

Typed attribution restates the landed #1705/#1758 identity fields through
ceiling-enforced constructors, and bounded denials never disclose foreign
object identity. Boot now provisions a nonzero boot identity and a nonzero
kernel secret with six CPUID-gated RDRAND draws; a missing feature, exhausted
draw, or degenerate block halts before audit authority or domain execution.
Installation mints exactly two move-only custodians from that secret: the
audit-chain signer and a native-verifier anchor. Key-bearing kernel and
verifier contexts are neither Copy nor Clone and erase key bytes on drop. The
anchor moves directly to the in-kernel verifier, while the untrusted handoff
still carries only public identity and a keyed binding tag. Replacement is
rejected for the life of the boot; a fresh boot provisions new material and no
cross-boot custody is retained.

The successful IPC `EndpointCreate` path is now the first wired live mutation.
Under the IPC lock it stages a root capability grant and relation projection,
preflights every fallible condition, records one typed `CapabilityGrant`
through the real verifier, and retires the relay record with its receipt. Only
after that complete audit transaction does an infallible same-lock state commit
run; audit or relay failure leaves objects, capabilities, relations, audit
sequence, and root unchanged, and the syscall is rejected as unaudited. Serial
emits the public boot/authority identity plus one public observation containing
audit sequence, class, rolling root, and retired state. It never emits a key,
anchor, or secret.

Kernel tests reconstruct the superseded public-only key
derivation from observed handoff fields and prove that forged handoff,
checkpoint, and acknowledgement material fail under the genuine trusted
anchor. Relay capacity is statically derived from the maximum
mandatory terminal/invalidation records one admitted atomic batch can produce
at the frozen ceilings: all 16 capability instances, 4 endpoints, 8 endpoint
queues, and the dying domain identity, for a reserve of 29. Ordinary records
cannot consume that headroom. Checkpoints are kernel-authenticated and bound
to boot/session, exact seq, root, codec version, and relay generation with a
keyed kernel tag and kernel-minted authority context instead of a public
verifier-recomputable digest or caller-selectable key; trusted restore
preserves the checkpoint's relay generation rather than resetting it. Verifier
acknowledgements additionally require a successful-fold receipt bound to the
live boot/session, relay generation, exact canonical frame, and source root.
The verifier is `no_std` and is used by the native kernel. Its handoff is
untrusted binding evidence: it names the authority id
and boot/session identity and carries only a kernel-keyed minting tag, never
verification material, so no handoff authenticates itself. The verifier
accepts its authority only through a kernel-origin anchor moved directly into
the live verifier and must bind the handoff against that anchor before any
verification session starts; structurally valid self-authenticated handoffs,
checkpoints sealed under forged contexts, and forged retirement receipts fail
closed.

A separate private host verifier (`kernel/tools/native-audit-verifier`)
independently decodes the canonical frames, folds the same root algorithm,
verifies checkpoints, and reports Invalid versus Incomplete without skipping,
extrapolating, or rewriting already-rooted events. Kernel tests cross-check
frames, roots, and checkpoints against that verifier. Sequence overflow and
relay-generation mismatch fail closed without partial commit; generation zero
is invalid on both sides.

No public WIT, hosted audit, live rekey, persistent escrow, durable retention,
cross-boot continuity, physical RNG certification, isolated verifier process,
or release readiness claim is included. The q35/TCG claim is limited to the
emulator fixture observing successful provisioning and one audited endpoint
mutation.

Residuals include broader IPC/domain lifecycle wiring, checkpoint restoration
in the live boot path, physical-machine/RDRAND certification, and operational
retention policy for later sequenced changes.
