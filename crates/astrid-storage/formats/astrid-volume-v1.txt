ASTRID HOSTED VOLUME FORMAT 1
=============================

Status: hosted-media recovery specification
Encoding: unsigned little-endian integers and canonical UTF-8 region names
Document line endings: LF

This is the hosted adapter for the path-free AstridVolume contract. The
principal store addresses named byte regions; it does not address host files or
directories. A bare-metal provider may use a different physical layout while
implementing the same region, transaction, and durability contract.

The hosted container starts with these exact eight bytes:

  41 53 54 56 4f 4c 31 00        ASCII "ASTVOL1" followed by NUL

Every following record is:

  offset  size  field
       0     8  magic = 41 53 54 52 45 47 31 00 ("ASTREG1" + NUL)
       8     8  total_record_length, including this header, name, and payload
      16     8  sequence, starting at 1 and increasing exactly by 1
      24     1  operation
      25     2  region_name_length
      27     8  logical_offset
      35     8  payload_length
      43    32  checksum
      75     N  canonical UTF-8 region name
    75+N     M  payload

Region names are relative, slash-separated UTF-8. They are non-empty, at most
512 bytes, and reject empty components, dot components, dot-dot components,
backslashes, control characters, leading slashes, and trailing slashes.

The checksum is the 32-byte output of a BLAKE3 derive-key hasher using context
"astrid volume record v1" over this exact concatenation:

  sequence[8]
  operation[1]
  region_name_length[2]
  logical_offset[8]
  payload_length[8]
  region_name[N]
  payload[M]

Operation codes are:

  1  create an absent empty region; payload is empty
  2  overlay payload at logical_offset in an existing region
  3  set an existing region length to logical_offset; payload is empty
  4  remove an existing region; payload is empty
  5  rename an existing source to an absent destination named by payload
  6  replace an existing destination named by payload with an existing source
  7  commit a metadata transaction; region is exactly
     system/volume-metadata-transaction and logical_offset is zero

A metadata-transaction payload begins with u16 mutation_count, followed by
mutation_count entries. Each entry is u8 kind (1 rename, 2 replace), then a
u16 source length and source bytes, then a u16 destination length and
destination bytes. Count is 1 through 1024. All mutations validate and become
visible as one record or none become visible.

Recovery admits only a contiguous sequence of complete, checksummed records
whose namespace transitions are valid. A physically incomplete final record is
an uncommitted tail and is truncated. A damaged length cannot hide a later
physically valid record; that is interior corruption and fails recovery. Write
payload checksums are streamed with bounded memory. Non-write payloads are
bounded to 2 MiB before allocation.

sync() makes every preceding admitted record durable. HostedFileVolume holds an
exclusive lock for the open lifetime. The engine close boundary releases that
lock even when other references to the closed engine remain.
